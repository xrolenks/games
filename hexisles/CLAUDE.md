# Hex Isles (`hexisles/index.html`)

Playable on one screen (pass the device around, or play against computer players) and over wifi with room codes (see **Wifi multiplayer**). Unlike Wild Wasteland, this code is written out normally (one statement per line, `//` comments are fine). Must stay an original game (own name, art, board, wording).

**Rules.** 2–4 players. Island of 24 hexes in rows of `ROWS` 4-5-6-5-4, shuffled each game: Jungle → Wood, Mudflat → Clay, Pasture → Wool (was Lagoon → Fish until 2026-11-17), Fields → Grain (was Grove → Fruit until 2026-11-11; `load()` renames `fruit` and `fish` in older saves: hexes, hands, ports, an open offer), Cliffs → Stone, plus one Volcano (nothing). Setup: in turn order and then back again, everyone places a town and a road; each starting town gives 1 of every land it touches. Then each turn: roll two dice, every hex with that number gives 1 resource per town and 2 per fort on its corners. A **7 is "low tide"** in Fire Mountain (no harvest, the roller picks one free resource) and moves the bandit in Classic (see below). Costs in `COST`: road Wood + Clay, town Wood + Clay + Wool + Grain, fort (upgrades a town) 3 Stone + 2 Grain. Towns can't be on neighbouring corners and (after setup) must touch your own road. **Trading with the bank:** `rate(p, r)` = how many of resource `r` player `p` gives for 1 of anything: `BANK` 4, or 3 with a town/fort on an "any" port, or 2 on that resource's port. **Ports:** `G.ports` = [{e: coast edge, r: resource or `'any'`}], made by `makePorts()` (one per resource + four "any", spread round `COAST`, the outside edges in order; shuffled each game; older saves get them in `load()`); `portAt(v)`; `usedPort(p, r, n)` = the port a trade at rate `n` goes through. Drawn by `port(o)` as a wooden **jetty** (Rick's request, 2026-11-17): a plank walkway on pilings from the beach out to a plank platform with the round sign standing on it; `portGeo(o)` gives its position and direction (`JETTY`, `DOCK` = platform middle, `BERTH`). Town 1 point, fort 2; first to `WIN` 10 wins. `MAXROADS` 15.

**Code.** Geometry is built once: `HEX` {x,y,v[6 corners]} (pointy-top, radius `S`), `VERT` {x,y,h hexes,n neighbour corners,e edges}, `EDGE` {a,b} (66 corners, 89 edges). The whole game is `G` (plain JSON, autosaved to `localStorage` key `hexisles-auto`, `ver` 1): `hex` [{t,n}], `pl` [{name,bot,res}], `b` buildings by corner {p,l 1 town/2 fort}, `r` roads by edge → player, `turn`, `phase` (`setup`/`roll`/`tide`/`discard`/`storm`/`main`/`over`), `su` (setup progress), `dice`, `win`, `log`. **Every move goes through `act(action)`** (`{t:'town',v}`, `{t:'road',e}`, `{t:'fort',v}`, `{t:'roll'}`, `{t:'pick',r}`, `{t:'trade',give,get}`, `{t:'end'}`, …), which checks the rules and returns true/false; `go(a)` = act + save + render. Keep it that way: wifi sends these same actions to the host. Placement rules: `okTown/okRoad/okFort`, `spots(p,what)`. Computer players: `botStep()` (on a 700 ms timer from `render`), `botMain`, `vScore`, `bestRoad/reach`. Drawing: the board is one SVG rebuilt by `drawBoard()` (board pictures from `glyph(t)`: tree on Jungle, peak on Cliffs). Cards, trade buttons, cost chips and port signs use `cardGlyph(t)` via `ico(t)`: the same as `glyph` except wood is a pile of cut logs and stone a chunk of rock (Rick's request, 2026-11-17); glowing `.spot` shapes show where you can build and invisible `.hit` shapes (`data-v` corner, `data-e` edge, `data-h` hex) take the clicks. `MODE` = what the player is placing; `VIEW` = whose hand is shown. Windows: `#m-setup` (players, Human/Computer), `#m-pick` (low tide), `#m-trade`, `#m-disc`, `#m-win`.

**Names (Rick's choices, 2026-11-11):** the blocker is **the bandit** (was "the storm"; the code still says `G.storm`, phase `'storm'`, `{t:'storm'}`, `botStorm`), drawn by `BANDIT` standing on the number disc; the deck is **progress cards** (was "island cards"); card `k` is **Guard** (was Storm Caller) and the award is "Most Guards".

**Classic mode: the bandit and progress cards** (Rick's rules, 2026-11-11; on when `G.deck` exists, so new Classic games only: Fire Mountain and older saves keep the low-tide 7). Rick described them with the usual board-game words (robber, knights, monopoly…); in the game they have Hex Isles' own names and art, keep it that way. **A 7:** every player holding more than `HANDMAX` (7) resources discards half, rounded down (`G.disc` {seat: count}, phase `discard`; computer players do it at once with `autoDiscard`, humans in `#m-disc` via `{t:'discard',p,res}`), then the roller moves the bandit (`G.storm` hex index, starts on the volcano; phase `storm`, `{t:'storm',h}`, must move) and that hex gives nothing while it's there. No stealing. **Cards:** `G.deck` = 25 shuffled codes from `CARDS` (`k` Guard ×14: move the bandit; `p` Landmark ×5: 1 secret point, never played; `r` Trailblazer ×2: `G.free` = 2 free roads; `h` Bounty ×2: any 2 resources; `m` Tribute ×2: take all of one resource from everyone else). `{t:'buy'}` costs Wool + Grain + Stone (`COST.card`); a player's cards are `P.cards` [{c, n: turn bought}]. `{t:'card',c,…}` plays one: only in `main`, one per turn (`G.played`), and not the turn it was bought (`n < G.tn`, the turn counter). `score(p)` includes Landmarks, `pubScore(p)` is what other players are shown until the game ends. `act(a, who)`: `who` is the seat doing it (the wifi host passes the sender's seat). Screens: `#b-buy`, `#mycards` (tap to play), the resource picker `openPick`/`PICK` (shared with low tide), `fillDisc`/`DWHO`/`DSEL`. Computer players: card plays at the top of `botMain`, `botStorm`.

**Fire Mountain mode** (`G.fire`, picked in the setup window or the wifi lobby via `FIRE`/`fillMode`; `newGame(cfg, fire)`). An original advanced mode: Rick asked for a "cities and knights" mode, which can't be copied from the existing board game, so this is Hex Isles' own take (a recurring danger plus something to defend with). The volcano is always inland. Every doubles roll adds to `G.rum`; at `RUMMAX` (3) `erupt()` picks one of six directions and lava runs in a straight line of hexes to the sea (`lavaLine(k)` using `HEXN`, stored in `G.lava` until the next eruption). Lava hexes (`scorched`) give nothing; a fort touching one drops back to a town unless it has a wall. **Walls** (`{t:'wall',v}`, `COST.wall` Clay + Stone, `G.b[v].w`, `okWall`) go on your own town or fort and are worth no points. Hexes beside the volcano are `fertile`: +1 resource per building. Computer players wall forts that lava could reach (`danger(v)`). Shown as a dark hex with an orange stream, a dashed ring for walls, "+1" on fertile hexes, and rumble dots under the volcano and in `#rumble`.

**Awards and player profiles (Rick's rules).** `awards()` runs after every successful move (the `act` wrapper around `act1`) once setup is over. **Longest route** (`G.lr`, both modes): the player whose longest unbroken chain of roads (`roadLen(p)`: no road counted twice, another player's town/fort cuts it) is at least `ROUTEMIN` 5. **Most Guards** (`G.la`, Classic only): most played (`P.kn`, `callers(p)`), at least `CALLMIN` 3. Each is worth `AWARD` 2 points (in `pubScore`). `holder()` decides: the holder keeps it until someone has strictly more (a tie changes nothing), and loses it if they drop below the minimum. The profiles (`#players`, one `.pl` per player: initial in their colour, points, resources/cards, route length and Guards played) sit at the **bottom right** on wide screens and right under the board on narrow ones; the player whose turn it is gets a faint tint of their colour (`.pl.cur`, `--c`); award badges `AWICON.route` / `AWICON.army` show on the holder's profile and move when the award does.

**Trading between players** (Rick's rules, 2026-11-16). On your turn (`main`): `{t:'offer', give, get}` (resource-count objects, checked by `cleanRes`; a resource can't be on both sides) sets `G.offer` = {from, give, get, yes: [accepted], no: [declined], x: [turned down by the offerer]} (`offerFix` adds missing lists for older saves; `offerState(o,p)`). Other players answer out of turn with `{t:'accept'}` / `{t:'decline'}` (`answer(p, t)`; `OUTOFTURN` lists the moves allowed off-turn, the wifi host uses the sender's seat). **Accepting doesn't swap anything:** the offerer then picks with `{t:'confirm',p}` (✓, does the swap) or `{t:'reject',p}` (✗) (`settle`). `offerDone()` closes the offer ("Nobody wanted that trade.") once no one has accepted and everyone has answered or been turned down. Computer players answer immediately when the offer is made (`botLikes`: they need spare cards, won't take fewer cards than they give, won't help someone within 2 points of winning) and never make offers themselves. `{t:'cancel'}` takes it back; nothing else is allowed while an offer is open (the bar's buttons are disabled then). Screens: the lower half of `#m-trade` (`OG`/`OW`, tap to add), and the **offer panel** `#offers` at the top right of the map (`fillOffers`, everyone sees it): the cards offered, each player's answer (Thinking…/Accepted/Declined/Turned down), ✓/✗ answer buttons on rows this screen can act for (`mySeat`: wifi = own seat, same screen = any human), ✓/✗ confirm buttons on accepted rows for the offerer, and Take it back.

**Layout (Rick's requests; latest wins).** Wide screens (`WIDE`, ≥1100px): the page is exactly the window (`#app` 100vh); the play window (`#boardwrap`) fills everything left of a slim 270px column (status line, your progress cards `#mycards`, Fire Mountain's `#rumble`, profiles at the bottom). `fitBoard()` gives the board a bigger viewBox there, so the island is smaller with open sea round it and empty sea along the bottom for **the bar** (`#bar`, laid over the bottom of the play window): the hand at the bottom left, then the action buttons (`#actions`), and on the right the dice with **End turn** beside them (`#barend`). Narrow screens and phones: tight viewBox, and the bar is ordinary page flow under the map (hand, buttons, dice + End turn), then profiles. The **log** is a small see-through box over the map's top-left corner (`#log`, last three lines, click to open). The **dice** (`#dice`, a button) glow with "Tap to roll" when it's your roll; clicking them is the only way to roll. The **hand** is real cards (`handHTML`: one `.rc` per resource held, fanned, count badge on the first of each kind).

**Action buttons** (`#actions`): one continuous row (Trade, Road, Town, Fort, then Card in Classic / Wall in Fire Mountain), each with its picture on top (`BICON`, `buildLabel`), a short name (`BSHORT`) and the cost as little coloured chips (`costChips`, full text in the `title`). Each build button sits in a `.bw[data-cost]` wrapper so hovering, even when disabled, shows `#tip` above the pointer (`showTip`): the cards it costs, gold for ones you hold and grey for missing, and the matching cards in the hand lift (`.rc.need`).

**Look (3D style, Rick's request).** `drawBoard()` starts with `DEFS` (a gradient per land from `COL[t]` = [light, dark, side colour], the number-disc gradient, a blur, `g-fieldlight`) plus `SEADEFS`. Layers: moving sea (`sea()`) → blurred island shadow → sandy cliff → beach → ports → each land as a raised tile (`TILE` .93 of its hex, dark side polygon 5 units lower, lit top, thin highlight) → `scene(t, i)` scenery at the 7 `SCENE` spots round the number disc (built from `glyph(t)` plus variations: ripples, mud; Fields use `wheat(i)` and Jungle `forest(i)` instead) → number disc → harvest glow → lava/bandit → roads (shadow, outline, highlight) → buildings (`piece`: lit front, shaded side, ground shadow) → click targets. Keep new board art in this style. **Drop animation:** `noteDrops()` compares the board with `SEEN` each draw and stamps new/changed pieces in `FELL`; `drop(key, val, inner)` wraps them in `<g class="fall">` (CSS `fall`, `DROPMS`) for roads, towns, forts and the bandit. `G.id` (new per game) stops a new game or a load from animating everything. The board is rebuilt every render, so looping animations use `sync(ms, off)` (a negative `animation-delay` from the clock) to carry on smoothly.

**Tilt and moving sea (2026-11-16).** The board SVG sits in `#view` (sea gradient, `overflow:hidden`, `perspective`, `position:relative`) and leans back with CSS `rotateX(20deg)`; the SVG has `overflow:visible` so its sea fills the corners the tilt opens up (clicks still hit correctly through the 3D transform, tested with real taps). `sea(sand)` draws drifting ripple patterns (`.wave`), twinkles at fixed spots (`SPARKS`, `.spark`), a shallow-water band and two rings of foam breaking on the beach (`.foam`).

**Wheat fields (2026-11-16).** Fields tiles are one continuous field by `wheat(i)`: clipped to the tile (`clipPath` `wc<i>`), rows of stalks back to front (front rows bigger, rows further back darker, a shadow band at each row's base), seeded per tile so it never changes, lit by `g-fieldlight`. Each row is a `.sway` group (CSS `skewX`, `sync()` with a per-row offset, so a wave rolls across). The "+1" fertile label is drawn after the scenery so the field doesn't hide it.

**Forest (2026-11-17, Rick's request: "a 3d forest similar to the wheat fields").** Jungle tiles are one thick forest by `forest(i)`, built like `wheat(i)`: rows of trees back to front (front rows bigger, back rows darker), about a third pines (three tiers, left side lit) and the rest round leafy crowns (shaded back, mid front, lit spot), seeded per tile. Only the floor and row shadows are clipped to the tile (`fc<i>`); trunks must stand on the tile but crowns may rise over the tile behind (drawn earlier), which gives the height. No trees near the number disc. Each row is one `.sway.tree` group (gentler, slower `swayt`) of five paths, one per colour, so it stays cheap to redraw.

**Clear numbers (2026-11-17).** `nearDisc(x0, y0, x1, y1, gap)` says whether a piece of scenery's box comes near the number disc (`DISCGAP` 22 by default). Forest trees (crown included, gap 18.5), wheat stalks and sheep (gap 18) inside it are left out, so every number sits in a clear patch. **Wheat** was redrawn for sharpness: each stalk is a thin stem plus an outlined pointed ear with a lit centre line and two whiskers (no more thick blurry strokes).

**Pasture (2026-11-17, Rick's request: a 3D pasture with fences and sheep).** `pasture(i)`: grass with lighter patches and tufts (clipped `pc<i>`), a post-and-rail fence round a paddock (hexagon `F` .86 of the tile) with a gap for a gate on the front-most side, and up to 7 sheep inside, back to front. The back fence is drawn before the sheep and the front fence after, so they overlap correctly. The sheep picture is `SHEEP` (fleece puffs `FLEECE`, dark face), also the Wool card picture. About 60% of sheep graze (`.graze`: dip forward now and then, `sync()`ed).

**Port trade boat (2026-11-17, Rick's request).** A bank trade through a port (`rate` < `BANK`) sets `G.ship` = {n counter, e port edge, p trader, give, get, k given}. `render()` calls `shipFx()`, which plays `sailShip()` when `n` changes (every screen including wifi guests, never on load, like `G.rolls`). The boat (`SHIP`, rocking `.bob`) and two crates (`crate(r, k)`) live in `#ships`, a second SVG over the board in `#zoom`: same box, viewBox (set in `fitBoard`) and `rotateX` tilt, `pointer-events:none`, never rebuilt by `render`, so the trip isn't restarted. Timeline (`SHIPMS` 4800, Web Animations with CSS `translate(px)`, which means board units on SVG): sail in from the open sea (0–35%), tie up beside the platform (not in front of the sign), the bought crate hops onto the platform and its card flies to the trader's hand or profile, the paid crate (×k) hops aboard, the boat turns (`scaleX` flips) and sails off the other way, fading at the end. Testing note: pausing these animations and setting `currentTime` doesn't paint in headless Edge screenshots, so use a timed `--virtual-time-budget` instead.

**Zoom and drag (2026-11-17).** `#view` > `#zoom` (new wrapper; holds `perspective`, `transform-origin:0 0`) > `#board` (keeps its `rotateX` tilt). `#zoom` gets `translate(ZX,ZY) scale(ZM)` from `applyZoom()`, which also keeps the middle of the window over the board. `ZM` runs from `ZMIN` .6 to `ZMAX` 3. The scroll wheel calls `zoomAt(k, x, y)` around the pointer. Dragging (mouse always; touch only once zoomed in, via `#view.zin{touch-action:none}`, so phones still scroll the page) starts after 6px, and a capture-phase click listener on `#view` swallows the drag's click (`DRAGGED`) so it never places a piece. The buttons `#zbtns` (+, −, ⟲ back to the whole island) sit at the right middle of the map. The thrown dice (`#roll`) are outside `#zoom` and keep their size.

**Dice and harvest (2026-11-16).** `G.rolls` counts rolls; when it changes (on every screen, including wifi guests; never on load) `showDice()` tumbles the bar dice (`dieHTML/drawDice`), calls `throwDice(G.dice)` and `harvestFx()`, all timed by `DICEMS` (2600 ms since 2026-11-18, Rick asked for a longer roll; was 1400; each die spins 2–3 full turns per axis). `throwDice`: two CSS 3D cubes (`#roll` inside `#view`; `.d3` > `.sh` shadow + `.lift` bounce > `.cube` of six faces `.f1`–`.f6`) fly in from the left, drop, bounce twice and tumble, ending with the rolled face towards the viewer (`FACE` turns, `VIEWX` lean so the near side shows); they stay `DICEHOLD` ms, then fade (`ROLLT`). `harvestFx` sets `HARV` {h: paying hexes, t: start}; once the dice land those lands glow (`.hglow`, drawn in `drawBoard`) and one small card (`.fly`, Web Animations) per resource flies in an arc from the land to the viewer's hand (if it's theirs) or that player's profile, which bumps on arrival. Nothing on a 7 or on bandit/lava hexes.

**3D board (2026-11-18, Rick's request: "more 3D and photorealistic, like Unity games").** A real WebGL scene made with **Three.js** (`three@0.160.0` from jsDelivr, via the `<script type="importmap">` in `<head>`; loaded by `load3D()` with dynamic `import()` only when needed: Water, OrbitControls and BufferGeometryUtils addons). It's the default view; the `2D`/`3D` button `#z-3d` in `#zbtns` switches (`set3D`, remembered in `localStorage` key `hexisles-view` = `'2d'` when off). If it can't load (offline) the flat map stays and the button's title says why. `D3` (declared near `NET`) = `{on, ready, failed, update, resize, reset, dolly, rect, screen, sail, three}`. Everything is in `init3D()`, near the end of the script. **It only draws**: the flat SVG board is still rebuilt every render (hidden with `#view.is3d #zoom{visibility:hidden}`, which also keeps the window's size), `drawBoard()` ends with `D3.update()`, and clicks on the canvas `#board3d` are raycast against invisible hit meshes (`hits` group, `userData` {v}/{e}/{h}) and become the same `go()` actions; a press that moved more than 6px is a camera drag, not a click. Don't name a class `d3`: the thrown dice use `.d3`. Look: painted sky dome (also the scene's light via PMREM, and what the sea mirrors; the three.js Sky was too bright and washed out shadows and the sea), sun `DirectionalLight` with soft shadows (`shadowMap.autoUpdate` off: `SHADOW = true` redraws them, done after each update and while pieces drop), three.js `Water` with a noise-made normal map, see-through sheets for shallow water and foam. All textures are painted in code (`noise`/`fbm`/`paint`, `LTEX` per land, `svgTex` turns SVG strings into textures for number discs, port signs, crates, "+1"). `build()` makes what's fixed for a game (key: `G.id` + lands + ports + mode): bevelled hex tiles (own material each, for harvest glow and darkening), scenery with `InstancedMesh` (`inst`; forest of pines and round trees, rocky peaks with snow, wheat stalk by stalk, paddock with fence and sheep, clay works on Mudflats (2026-11-18, Rick's request: "clay mining and kilns": six slots round the disc shuffled per tile; a brick beehive **kiln** on a stone base always in a back slot so it never hides the number, with a glowing fire mouth (`L.mouth`, lava material), chimney, smoke puffs and a log pile; a dug **clay pit** in a front slot: dark hole `L.hole`, raised clay rim `L.rim`, two clay heaps and a shovel; plus a puddle with reeds and a brick stack), volcano cone with lava pool, flickering light and smoke puffs), number discs (turn to face the camera every frame, like the bandit), jetties and port signs (sprites). Wheat, grass, reeds and trees sway in a shader (`sway()`). `dynamic()` remakes the rest each update: roads (coloured beams), towns (house + roof + chimney), forts (tower + battlements + flag), walls (stone ring), bandit (hooded figure, `BANDIT3`), lava tube, rumble balls, build spots (pulsing white) and hits. Drops use `FELL` like the flat map. Camera: OrbitControls (drag turns, wheel/pinch zooms, right-drag slides, target kept within 260 of the middle); on phones `touch-action: pan-y` so a vertical swipe still scrolls the page; `fit()` frames the island (wide screens leave room for the bar). The trade boat in 3D is `D3.sail` (`sailShip` hands over), same timeline, and harvest cards start from `D3.rect(i)`. **Testing:** the Browser pane is usually hidden, which pauses the animation loop and makes screenshots crop strangely: set `resize_window` to a fixed size (800x600 worked) before screenshots. `D3.screen(x, y, z)` gives the screen spot of a board point (y = height, `TOP` 9 = tile top) for real clicks; `D3.three` exposes the renderer, scene and camera. Smoke puffs come from `puff(x, y, z, size, start)` (volcano size 1, kiln chimneys .4). If Rick has a game open in another tab, test in a tab without calling `go()` (it saves over `hexisles-auto`), or back the save up first.

**Wifi multiplayer.** Uses PeerJS, loaded from `PEERJS` (unpkg, pinned version) only when someone hosts or joins; besides Three.js for the 3D board, it's the game's only outside dependency and needs internet (PeerJS's free cloud server introduces the browsers, then they talk directly). `NET` = `{role:'host'|'guest', seat, name, code, …}` (`{role:null}` for a same-screen game). The host opens a `Peer` with id `ROOM` + a 4-letter code; guests connect to it. **The host's browser runs the real game**: guests' `go(a)` sends `{t:'act',a}`, the host checks it's that seat's turn and runs `act`, and `render()` on the host ends with `broadcast()` = `{t:'state',g:G,seat}` to everyone (the whole game each time, so hands aren't secret from someone reading the network; the screen only shows your own). Other messages: `hello` (guest's name), `you` (name after de-duplicating), `lobby` (names), `full`. `myTurn()` decides whose screen can act (wifi: `G.turn===NET.seat`; same screen: any human). Computer players run only on the host. Windows: `#m-net` (name, Host, code + Join), `#m-lobby` (code, players, computer players, Start; `fillLobby/sendLobby`). A guest who drops is marked `gone` and a computer plays for them (`hostDrop`); joining again with the same name and code gives the seat back. Someone joining mid-game watches (seat −1) until the host starts the next game (New game → lobby → Start). Guests never write the autosave. Not done: if the **host** closes or reloads the page the wifi game ends (the save loads as a same-screen game).

**Testing.** `http://localhost:8765/games/hexisles/` (server in the root `CLAUDE.md`). In the console, a whole computer game runs instantly: `newGame([{name:'A',bot:1},{name:'B',bot:1}]);while(G.phase!=='over')botStep()` (about 30–65 rolls). To rig a roll, queue values into `Math.random` (`rnd(n)` = `Math.floor(Math.random()*n)`). Clear `hexisles-auto` afterwards.
